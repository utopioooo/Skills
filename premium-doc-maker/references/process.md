# 生产流程

本文件规定"从素材到可交付 zip"的七个阶段、每阶段的产物与门禁。
视觉规范见 `design-system.md`，写作标准见 `content-blueprint.md`。

---

## 1. 总览

| 阶段 | 输入 | 产物 | 门禁（不过不进下一阶段） |
|---|---|---|---|
| 0 规格 | 用户需求 | 规格卡（课程/读者/讲次/风格/品牌/年份） | 用户确认 |
| 1 大纲 | 素材 | `outline.md` | 每讲 4~6 小节、有摘要、依赖顺序合理；用户确认 |
| 2 样张 | 大纲 + 风格包 | `01.html`（成品） | 对齐 `examples/golden`；用户确认视觉与密度 |
| 3 骨架 | 大纲 | `manifest.json` + `index.html` + `NN.html` | scaffold 无报错 |
| 4 正文 | 骨架 | 全部正文页 | 每讲满足内容标准 |
| 5 验收 | 全部页面 | 验收报告 | `validate.py` 0 error |
| 6 交付 | 通过验收的目录 | `<课程名>.zip` | 解压后双击 index 可读 |

阶段 0、1、2 是三个**人工确认点**。跳过任意一个，返工成本都会放大到整套文档。

---

## 2. 大纲格式（`outline.md`）

`scaffold.py` 直接解析这个文件，所以格式必须严格。

```markdown
# 课程大纲：C++高性能编程与系统开发

- 课程名：C++高性能编程与系统开发
- 副标题：深入探索现代 C++ 性能极限，构建高效可靠的软件系统。
- 品牌：翎光技术文档
- 作者：翎光技术文档
- Slogan：探索技术深度，挖掘知识价值
- 年份：2026
- 风格：blue-ink

## 第 1 讲 内存管理与性能
- 摘要：内存布局、栈与堆、自定义分配器、内存池
- 阶段：基础认知
- 能力点：能定位内存瓶颈并选择分配策略
- 前置：无
- 难度：进阶
- 时长：45

### 小节
1. 引言：内存去哪了
2. 一、栈与堆的边界
3. 二、自定义分配器
4. 三、方案对比与选型
5. 四、总结与最佳实践

## 第 2 讲 CPU 缓存与数据局部性
- 摘要：缓存行、伪共享、数据对齐、访问模式
- 阶段：核心机制
### 小节
1. 引言：缓存决定性能上限
2. 一、缓存层次与缓存行
3. 二、伪共享与数据布局
4. 三、访问模式与选型
5. 四、总结与最佳实践
```

规则：

- 头信息是 `- 键：值`，支持课程名、副标题、品牌、作者、Slogan（口号）、年份、风格。
- 每讲以 `## 第 N 讲 标题` 开始；`N` 可省略，省略时按出现顺序编号。
- 讲内元信息：摘要、阶段、能力点、前置；可选 难度（入门/进阶/实战/专家）、时长（纯数字，分钟）。
- `### 小节` 之后是编号列表，**4~6 条**，每条就是正文一个 `<section>` 的 `<h2>`。
- 阶段相同的连续讲次会在目录页合并成一组；阶段变化即开新组。建议 3~5 个阶段。

没有大纲时也可以用简表（`.txt` 每行 `标题 | 摘要 | 阶段`，或 `.json` 数组），但会退化成默认五段式，不推荐用于正式产品。

## 3. 阶段细则

### 阶段 0 — 规格卡

先写下来再开工：

```
课程名：
一句话副标题（学完能做什么）：
目标读者：
讲次数量：            （默认 20~30）
风格包：              （默认 blue-ink）
品牌名：
作者：                （显示在每页页脚；默认同品牌）
口号（slogan）：      （显示在每页页脚）
年份：
是否要 PDF / 封面：    （可选）
是否要试读页/水印：    （可选）
```

品牌、作者、口号只写在 manifest 里，由模板渲染到页脚；不要逐页手写。

### 阶段 1 — 素材提炼

1. **抽能力点**：列出"读者学完能做的事"，合并同类，得到讲次候选。
2. **排依赖**：被依赖的先讲（内存布局 → 内存池 → 分配器）。
3. **写摘要**：写不出 3~4 个关键词，说明边界不清，重切。
4. **配主图主表**：每讲至少能想出一张结构图 + 一张对比表；想不出说明内容太抽象。
5. **配代码**：每讲至少 2 段可运行代码；素材没有就按主题补标准示例。
6. **写收尾清单**：把要点压成 4~6 条可执行准则。
7. **查重**：同一概念全书只深入讲一次，其余用交叉引用。
8. **建术语表**：按 `examples/glossary.md` 建一份，确定每个核心概念的唯一中文叫法与首次出现讲次。

### 阶段 2 — 样张

只做第 1 讲，目标是与 `examples/golden/01.html` 同等密度：

- 4~6 个小节，每节"结论 → 机制 → 代码/图 → 对比/陷阱 → 实践"
- 2 段代码、2 张表、2 张图、1 个升华收尾
- 深色/浅色都看一遍，375px 宽看一遍

用户确认后再进入阶段 3。

### 阶段 3 — 骨架

```bash
python scripts/scaffold.py --outline outline.md --outdir ./out
```

- 已存在 `manifest.json` 时会拒绝执行；重建整门课加 `--force`，只重建目录页用 `--index-only`。
- 生成后先 `validate.py` 跑一次，确认"只剩内容类错误"，说明结构正确。

### 阶段 4 — 正文

按 `markup-cookbook.md` 填每个 `<section>`。顺序建议：

1. 先写全部 `<h2>` 下的第一段结论（占位也要是完整判断）
2. 再补代码与图表（先保证载体数量达标）
3. 最后写对比、陷阱、最佳实践
4. 回术语表检查：有没有表外叫法、有没有重复括注英文

每讲填完立刻单页验收：

```bash
python scripts/validate.py --file ./out/03.html
```

### 阶段 5 — 验收

```bash
python scripts/validate.py --dir ./out
```

三类错误必须清零：

- **结构类**：小节数、载体数、代码/表格/SVG 数量、空小节
- **一致性类**：标题、页脚、讲次、目录卡片、翻页、交叉引用
- **契约类**：令牌、裸色值、脚本数、外链、转义、id 重复

warning 逐条判断：字数低于 800 通常意味着讲得太薄；高于 2200 通常该拆成两讲。
新增的内容质量提示（warning）也要看：空洞表达、无来源性能数字、表格行列数、总结缺 4~6 条准则。

机器验收之后再做**视觉验收**（`preview.py` 起服务器或 `--screenshot` 截图），检查 1280/375、
浅色/深色下的溢出与重叠；再做**抽样人审**（至少 20% 讲次）：读一段，确认没有车轱辘话、
数字有出处、代码能跑。内容评审表见 `SKILL.md` 文末。

有编译器的环境可以再跑一次可选的代码检查（缺头文件的片段会误报，只作提示）：

```bash
python scripts/check_code.py --dir ./out
```

### 阶段 6 — 交付

```bash
python scripts/pack.py --dir ./out
```

`pack.py` 会先跑验收，不通过直接中止。zip 顶层是课程文件夹，内含 README、LICENSE、QA 报告、
manifest 与全部 HTML。

## 4. 增量操作

### 补一讲

1. 在 `outline.md` 末尾追加新讲（含 4~6 个小节标题）。
2. 运行：

   ```bash
   python scripts/scaffold.py --add --outline outline.md --outdir ./out
   ```

   已有正文一律不动，只为新增讲次生成壳并重建目录页。`--add` 按位置对齐：
   改动已有讲次的标题不会被误判成新讲，只会打印差异提示（以 manifest 为准）。
3. 运行 `python scripts/renumber.py --dir ./out`，把上一讲的"下一讲"链接、页脚、目录卡片一次性对齐。
4. 填内容 → `validate.py` → 打包。

如果新讲要插在中间：先追加到末尾，再调整 `manifest.json` 里的 chapters 顺序，跑 `renumber.py` 自动改名与同步。
要改已有讲次的标题/摘要，直接改 `manifest.json`，再跑 `renumber.py`；不要改大纲后指望 `--add` 同步。

> `renumber.py` 依赖 2.x 模板锚点（`data-n`、`data-title`、`.pager`、`manifest`）。
> 1.x 旧页面没有这些锚点，先按 CHANGELOG 的迁移提示重新生成，再重编号。

### 删一讲 / 调顺序

1. 调整 manifest 的 chapters 顺序（删掉不要的项）。
2. 跑 `renumber.py`；被移动的文件会自动改名，页脚与翻页同步。
   被删讲次留在磁盘上的旧页面会移到 `<课程目录>/_trash/`，不会丢数据；
   加 `--keep-orphans` 则改为报错中止、不做任何修改。
3. 跑 `validate.py`，重点看交叉引用是否还指向存在的讲次（指向已删讲次会报错）。

### 换品牌 / 年份 / 副标题

改 `manifest.json` 顶层字段 → `renumber.py` → `validate.py`。

### 只重建目录页

```bash
python scripts/scaffold.py --index-only --outdir ./out
```

不要手改 `index.html`，它完全由 manifest 渲染。

### 换风格

见 `style-protocol.md`。已写好的正文不用重写：换风格后用 `--force` 重建会丢内容，正确做法是重新 scaffold 到新目录，再把各讲 `<section>` 内容搬过去（组件类名是风格契约的一部分，保持不变）。

## 5. 验收不过怎么办

| 报错 | 处理 |
|---|---|
| 残留占位符 / 待撰写 | 该小节还没写，补内容并删掉提示注释 |
| 空小节 | 至少加一段正文 + 一个载体 |
| 代码块应为 2~6 个 | 补"朴素写法 vs 优化写法"对照 |
| 表格必须包在 .table-wrap | 用 cookbook 的表格片段重包 |
| 令牌与风格包不一致 | 页面过期，重新 scaffold（先备份正文） |
| 裸色值 | 改成 `var(--token)`，或把新颜色加进 tokens.css 两套主题 |
| SVG 内出现 var() | 换成字面量 hex |
| 跨讲重复段落 | 保留一处，另一处改写或换成交叉引用 |
| h2 编号混用 | 全书统一为中文序号或阿拉伯序号 |
| 页脚/标题不一致 | 改 manifest 后跑 renumber，不要逐页手改 |

## 6. 完工定义（Definition of Done）

- [ ] `validate.py --dir` 退出码 0，且 warning 已逐条处理（建议再跑 `--strict`）
- [ ] 内容评审表通过，至少抽查 20% 讲次
- [ ] 目录页 30 张卡片全部可点，讲次连续无缺号
- [ ] 每讲在浅色/深色、1280px/375px 下均无溢出、无低对比度（`preview.py`）
- [ ] 每讲 ≥1 张 SVG、≥1 张表、≥2 段代码，正文 800~2200 汉字
- [ ] 全书术语一致（同一概念同一叫法），交叉引用有效
- [ ] 任意位置都没有未转义尖括号，性能数字有来源
- [ ] 页脚品牌 / 作者 / 口号、共 N 讲、年份与 manifest 一致
- [ ] `pack.py` 打包成功，解压后是独立课程文件夹，双击 `index.html` 可读
- [ ] README / LICENSE / QA.md 里的课程名、讲次数、品牌、作者与 manifest 一致
