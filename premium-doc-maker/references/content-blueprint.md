# 内容标准

本文件规定"一讲怎么切、每节怎么组织、写到什么密度"。视觉规范见 `design-system.md`。

> 本文件与主题无关。示例用 C++，换 Rust / K8s / 量化时，规则不变，示例按主题替换。

---

## 1. 核心原则：一讲 = 一个可交付的能力点

判断标准：读者学完这一讲，**能独立完成一件之前做不到的事**，或**能对一个既有方案做出有依据的选型决策**。

- 好标题：`内存管理与性能`、`容器与算法性能`、`零拷贝技术` —— 名词短语，指向能力。
- 坏标题：`浅谈内存`、`关于容器的一些思考`、`XX 概述` —— 话题，不是能力点。

每讲摘要 = 3~4 个关键词短语，顿号分隔。它同时是 header 副标题和目录卡片文案，写的时候直接复用。

---

## 2. 标准骨架（4~6 个 `<section>`）

| # | 段落 | 作用 | 常见 h2 | 典型载体 |
|---|---|---|---|---|
| 1 | 引言 | 为什么需要、度量什么、边界在哪 | `引言：…`、`概述` | 一段定性判断 + 指标表 |
| 2~N-2 | 主体（2~3 节） | 逐个讲核心机制 | 每个机制一节 | 代码 + 图 + 陷阱 |
| N-1 | 对比 / 选型 | 把散点收敛成决策依据 | `…对比与选型` | 对比表 + 架构图 |
| N | 总结与最佳实践 | 可执行清单 + 升华 | `总结与最佳实践` | 有序列表 + 金句 |

变体：

- **案例讲**：每个 case 一节，内部走 `目标 → 架构图 → 选型表 → 核心代码`。
- **工具讲**：`为什么 → 工具 A → 工具 B → 综合实战 → 工具对比`。
- **原理讲**：`问题背景 → 机制 1 → 机制 2 → 机制 3 → 实践总结`。

小节数低于 4：讲得太薄，补机制或案例；高于 6：拆成两讲。

---

## 3. 每个知识点的五步法（h3 级）

1. **结论先行**：第一句直接给判断，不铺垫。
   > 通过把多次小 I/O 合并成少量大 I/O，系统调用次数下降一个数量级，吞吐随之提升。
2. **机制/原理**：讲清底层发生了什么，不堆形容词。
3. **代码佐证**：一段可直接用的完整片段，中文注释解释"为什么"。
4. **对比/陷阱**：表格或 `warning-box`，给量化差异、适用边界、常见误用。
5. **最佳实践**：`tip-box`，给具体参数或准则（"缓冲区取磁盘块 4KB 的整数倍"）。

五步不要求每节全有，但**一个 section 不能只有第 1、2 步**——那是空小节。

---

## 4. 颗粒度与预算

| 维度 | 目标 | 硬性范围（validate 检查） |
|---|---|---|
| 每讲汉字数 | 800~2200 | 600~3000 |
| 小节数（h2） | 4~6 | 4~6 |
| 每个 h3 | 150~400 字 + 恰好一个载体 | — |
| 每节 h3 数 | 2~4 | — |
| 代码块 | 2~6（中位 4） | 2~6 |
| 表格 | 1~3（中位 2） | 1~3 |
| SVG 图 | 1~6（中位 2） | 1~6 |
| 每讲主图 / 主表 | 各至少 1 | 由数量下限保证 |

- 超过 500 字还没进代码/图表 → 拆成两个 h3。
- 一节连排 3 个代码块却没有讲解 → 拆节或删代码。
- 目标读者是"能照着做"的工程师，不是"知道有这么回事"的爱好者：每个机制都要落到可执行动作。

---

## 5. 载体选用

| 要表达的内容 | 载体 | 组件 |
|---|---|---|
| 怎么做、API 怎么用 | 代码块 | `.code-block > pre > code` |
| 多方案差异、选型、指标、复杂度 | 表格 | `.table-wrap > table` |
| 系统分层、数据流、处理管道、时序 | 手写 SVG | `.svg-container` |
| 版本演进、标准迭代、固定步骤链 | 时间线 | `.timeline` |
| 并列概念 / 场景 / 工具（3~6 个） | 网格卡片 | `.grid > .card` |
| 两方案正面对照 | 双栏 | `.comparison` |
| 术语、API 名、关键数字 | 行内强调 | `.highlight` / `.keyword` |
| 建议、参数经验值 | 提示框 | `.tip-box` |
| 误用、陷阱、反模式 | 警告框 | `.warning-box` |
| 本节结论、代码引导 | 要点框 | `.key-point` |
| 复杂度标注 | 徽章 | `.complexity-badge` / `.badge` |

**一图胜千言，但装饰性插图是负资产。** 图必须承载结构、流向或对照关系；画不出信息就删掉，不要凑数。

## 6. 代码规范

- **自包含**：给必要 `#include` / `use`，类型与变量完整，能直接编译或运行。
- 注释中文，解释"为什么这么写"和"性能含义"，不逐行翻译。
- 高性能主题优先给**错误写法 vs 正确写法**或**朴素 vs 优化**的对照。
- 命名全书统一（C++：`snake_case` 变量 / `PascalCase` 类型；Rust：`snake_case` / `PascalCase`）。
- 平台相关 API（`mmap`、`io_uring`、`epoll`）在正文或 `note` 里标明适用平台。
- 长度 15~40 行；超出只保留关键片段，用 `// ... 省略非关键部分` 标注（validate 允许这一句）。
- 任何位置的 `<` 都必须转义为 `&lt;`（正文、行内 `<code>`、`<pre>` 一样；`<int>` 会被浏览器吞掉）；
  `&` 在可能构成实体时写成 `&amp;`。
- 性能数字必须标来源：`实测（i7-12700，GCC 13，-O2）` / `典型值` / `据 Intel SDM`。禁止"提升 300%"这类无出处数字。

---

## 7. 表格规范

只用于四类目的，写表头前先明确是哪一类：

1. **对比型**：`方案 | 机制 | 优点 | 适用场景`
2. **选型型**：`技术 | 典型应用 | 性能提升`
3. **指标型**：`性能指标 | 描述 | 常用工具/方法`
4. **复杂度型**：`操作 | 时间复杂度 | 说明`

规则：3~6 行、2~4 列；单元格写短语；首列加 `<strong>`；表头用 `<th>`；整表包在 `.table-wrap` 里（窄屏横向滚动）。

---

## 8. 开篇与收尾

- **开篇第一段**回答"为什么需要 / 不这么做会怎样"，一句话定性，再展开。
- **结尾小节**用有序列表给 4~6 条可执行准则（能在明天上班时照做的那种）。
- **最后一段**是升华金句，把技术上升到方法论或权衡观：
  > 高性能编程不仅是写更快的代码，更是在抽象、可维护性与极致效率之间做明智的权衡。

金句只写一句，不要连续排比。

---

## 9. 章节编号

全书二选一，不许混用（validate 会跨讲统计）：

- 中文序号：`一、内存布局` / `二、栈与堆`
- 阿拉伯序号：`1. 内存布局` / `2. 栈与堆`

`引言`、`总结与最佳实践` 可以不带序号，其余小节必须统一带序号。
标题可带英文原名括注：`三、RCU（Read-Copy-Update）`。

---

## 10. 交叉引用

同一概念全书只深入讲一次，后续用交叉引用。写法必须带 `data-ref`，这样 `renumber.py` 才能同步编号：

```html
<p>无锁队列的实现细节见 <a href="07.html" data-ref="7">第 7 讲</a>。</p>
```

`data-ref` 的值是目标讲的编号，`href` 是目标文件，正文里写「第 N 讲」。三处不一致会被 validate 判错。

---

## 11. 禁忌

- 禁止空洞过渡："下面我们来看…"、"相信大家已经了解…"、"总的来说"。
- 禁止"浅谈 / 初探 / 漫谈"这类标题词。
- 禁止把官方 API 列表直接搬进来——必须有取舍理由和对比。
- 禁止无出处的具体性能数字。
- 禁止跨讲复制段落（validate 会查重复与近似重复）。
- 禁止标题里用 emoji（印刷与跨平台观感不稳定）。
- 禁止在正文暴露 AI 痕迹、免责声明、与主题无关的自我指涉。
- 禁止在正文里手写品牌名、作者、口号——它们只在 manifest 定义一次，由页脚模板渲染。
- 禁止"此处省略"式偷懒；只允许 `// ... 省略非关键部分` 这一种写法。
- 禁止照抄原素材文案：要做**改写与重组**，保留事实与技术判断，重写表达；引用他人观点时注明来源（不要放外链，写在正文里）。

---

## 12. 目录页文案

- 课程副标题：一句话说清"学完能做什么"。
  > 深入探索现代 C++ 性能极限，掌握从内存管理、并发编程到系统设计的核心技能。
- 课程说明：`本课程共 N 讲。每讲由若干小节组成，配有可运行代码、对比表与手写 SVG 图…`
- 每张卡片：序号 + 标题 + 3~4 个关键词摘要 + 「开始学习」。
- 卡片按阶段分组（3~5 组），组名用能力阶段而不是"第一部分"。
- 页脚固定展示「品牌 · 口号」「作者：…」「课程名 · 共 N 讲 · 年份」；三者来自 manifest，
  不要在目录页或正文里另写一份。

---

## 13. 示例骨架（可直接套）

```
header:  讲标题 / 关键词摘要 / 《课程名》第 N 讲

section 1  引言：为什么需要 X
  p        定性判断 + 一句话结论
  table    指标或分类表

section 2  一、核心机制 A
  p        A 的原理
  code     A 的最小可用示例
  tip-box  最佳实践

section 3  二、核心机制 B
  p        B 的原理
  svg      机制示意图
  code     B 的代码
  warning-box 常见陷阱

section 4  三、A 与 B 的对比与选型
  table    对比 / 选型表
  svg      架构或决策图

section 5  四、总结与最佳实践
  ol       4~6 条准则
  p        升华金句

footer:   品牌 / 课程名 / 第 N 讲（由模板与 renumber 维护）
```
